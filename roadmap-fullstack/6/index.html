React, observability, security

P1

🎭Аналогия

React-компонент - форма для заполнения: props - то, что в форму принесли снаружи, state - то, что меняется прямо на месте, пока её заполняют. useEffect - секретарь, который что-то делает при открытии формы (например, звонит на склад за данными) и обязан знать, когда именно перезванивать - вот зачем dependency array.

📖Теория

React - survival минимум

function Tasks() {
  const [items, setItems] = React.useState([]);

  React.useEffect(() => {
    fetch("/api/tasks")
      .then(r => r.json())
      .then(setItems);
  }, []);

  return items.map(x => <div key={x.id}>{x.name}</div>);
}

const [items, setItems] = React.useState([]);
       │       │                        └ начальное значение state
       │       └ функция обновления state - вызывает re-render
       └ текущее значение state

React.useEffect(() => { ... }, []);

Термин Смысл
component функция, возвращающая UI
props входные данные компонента
state изменяемое состояние UI
useState хранит state
useEffect side effect: fetch/subscription; dependencies важны
key стабильная идентичность элемента списка
controlled input value хранится в state
SPA навигация/рендеринг в браузере, API отдельно

Fullstack-цепочка: React вызывает API → backend валидирует → service → PostgreSQL → JSON → React обновляет state. У vacancy-tracker фронтенд сегодня - vanilla JS (templates/index.html, loadRows()), не React, но паттерн fetch → .json() → перерисовка тот же самый.

Частая поломка: убрать [] у useEffect целиком - эффект выполняется после каждого рендера, fetch вызывает setItems, setItems вызывает рендер, рендер снова запускает эффект - бесконечный цикл запросов. Один из самых частых React-вопросов на собеседовании.

Observability - системная картина

Сигнал Для чего
Logs что произошло, контекст события
Metrics сколько/как часто/насколько плохо
Traces путь запроса через компоненты
Health/liveness процесс жив
Readiness сервис способен обслужить запрос с нужными зависимостями

Alert - это симптом, не диагноз: после алерта нужна независимая проверка (см. Sber_KIRB_Unified_Stand_Prep.md - тот же принцип на инфраструктурной стороне). Дашборд без цепочки alert → triage → recovery не считается готовым мониторингом.

Security - минимум без придумывания опыта

Тема Суть
Authentication vs Authorization кто ты vs что тебе разрешено
401 vs 403 не аутентифицирован vs аутентифицирован, но запрещено
Пароли salted password hash, никогда plaintext
JWT подписанный token, не шифрование по умолчанию; проверять exp/aud/iss
OAuth2 делегирование авторизации; access/refresh token - разные роли
SQL injection параметры запроса, не конкатенация SQL
CORS browser policy, не серверный firewall
Secrets env/secret store, не Git

vacancy-tracker уже использует реальный пример - Basic-аутентификация через app/auth.py middleware для доступа снаружи localhost. Это не выдуманный пример - можно открыть код и разобрать построчно.

🔧Практика

  • Прочитать templates/index.html, найти loadRows() - сопоставить с React-паттерном fetch → .json() → setState, назвать, что там играет роль state в vanilla JS-версии.
  • Найти в app/main.py подключение BasicAuth middleware, объяснить разницу между 401 (не прошёл auth) и 403 (прошёл, но не разрешено) применительно к этому коду.
  • Спроектировать вслух /ready-эндпоинт для vacancy-tracker, который в отличие от /health реально проверяет доступность PostgreSQL (SELECT 1).

💥Сломай намеренно

  • В песочнице (codesandbox/аналог) убрать [] у useEffect из примера выше - увидеть бесконечный цикл запросов своими глазами, не только прочитать про него.
  • Представить, что X-Request-ID/логи случайно включают пароль пользователя - объяснить, почему это находка для security review, а не мелочь.
  • Заменить параметризованный SQL-запрос на конкатенацию строки с пользовательским вводом - показать классическую SQL injection на примере (без выполнения на боевой БД).

✅Задание

Можешь прочитать и объяснить чужой React-компонент (props/state/useEffect/dependency array) без подготовки, спроектировать /ready-эндпоинт с проверкой зависимости, и не путать 401/403, authentication/authorization на конкретном примере.

❓Вопросы с ответами

Как React получает данные и обновляет UI?

useEffect с fetch при монтировании (или по изменению зависимостей), результат кладётся в state через setState, изменение state триггерит re-render компонента с новыми данными.

Что такое useEffect и почему dependency array важен?

Side-effect функция, выполняемая после рендера. Dependency array определяет, когда её перезапускать: пустой массив - один раз при монтировании, отсутствие массива - после каждого рендера (риск бесконечного цикла при setState внутри), список зависимостей - при их изменении.

401 vs 403?

401 - клиент не прошёл аутентификацию (кто ты - неизвестно или неверно). 403 - аутентификация прошла, но действие запрещено (кто ты - известно, прав недостаточно).
