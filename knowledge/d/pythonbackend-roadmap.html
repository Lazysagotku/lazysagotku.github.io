🔵 Фаза 1 — Идиомы и продвинутый Python

Цель: писать на Python не "как на C# с другим синтаксисом", а на его собственных идиомах

Темы

  • [ ] 1.1 Типизация — mutable vs immutable, что реально копируется при присвоении
  • [ ] 1.2 List/dict/set comprehensions — когда идиоматично, когда усложняет
  • [ ] 1.3 args / kwargs — 🎯 уже назван самим Иваном как пробел (объяснено 8 июля)*
  • [ ] 1.4 Итераторы и генераторы — yield, ленивые вычисления (мост от C# IEnumerable/yield return)
  • [ ] 1.5 Декораторы — свои декораторы, functools.wraps, параметризованные декораторы
  • [ ] 1.6 Контекстные менеджеры — with, __enter__/__exit__, contextlib (мост от C# using/IDisposable)
  • [ ] 1.7 ООП в Python — dunder-методы (__eq__, __repr__, __hash__), @property, dataclasses (мост от C# record)
  • [ ] 1.8 Type hints — typing модуль, Optional/Union, статическая проверка через mypy

🎯 Итоговое задание

Переписать один из существующих реальных Python-скриптов (например CSV-импорт) с применением: типизации через hints, генератора вместо списка там, где уместно, контекстного менеджера для работы с файлом/соединением, dataclass вместо словаря для структуры данных.

🟢 Фаза 2 — Async/Concurrency

Цель: понимать разницу async/threading/multiprocessing и не путать их применение

Темы

  • [ ] 2.1 GIL (Global Interpreter Lock) — что это и почему threading не даёт настоящего параллелизма для CPU-bound задач
  • [ ] 2.2 asyncio — event loop, async/await, Task (мост от C# Task/async-await — тот же паттерн, разный рантайм)
  • [ ] 2.3 Когда threading, когда multiprocessing, когда asyncio — I/O-bound vs CPU-bound
  • [ ] 2.4 aiohttp/httpx — асинхронные HTTP-запросы
  • [ ] 2.5 Semaphore/Lock в asyncio — та же логика, что SemaphoreSlim/lock в C# (Phase3_Advanced.md §3.5), просто другой API

🎯 Итоговое задание

Написать скрипт, параллельно обращающийся к нескольким внешним API (например тестовым эндпоинтам) через asyncio.gather + Semaphore для ограничения одновременных запросов — прямая параллель уже пройденному SemaphoreSlim-примеру из C#-курса.

🟡 Фаза 3 — Web-фреймворк (FastAPI) — 🔗 частично готово

Цель: строить REST API на современном Python-стеке (мост от ASP.NET Core)

Темы

  • [ ] 3.1 FastAPI основы — маршрутизация, path/query параметры, статус коды
  • [x] 3.2 Pydantic — валидация данных, модели запроса/ответа (есть в Python_Backend_Crash_Course.md, День 1)
  • [x] 3.3 Dependency Injection — Depends() (мост от C# DI-контейнера) (есть в крэш-курсе, День 2)
  • [x] 3.4 Strategy pattern через ABC (есть в крэш-курсе, День 1)
  • [ ] 3.5 Middleware в FastAPI — свой middleware (мост от ASP.NET Core middleware, Фаза 5.8 C#-роадмапа)
  • [ ] 3.6 Background Tasks (частично есть в крэш-курсе, День 2 — проверить/расширить)
  • [ ] 3.7 Аутентификация — OAuth2/JWT в FastAPI (мост от C# JWT, Фаза 5.9)

🎯 Итоговое задание

CRUD REST API (тот же "Task Manager", что и в C#-роадмапе Фазе 5) — но на FastAPI, чтобы напрямую сравнить подход двух экосистем к одной и той же задаче.

🗄️ Фаза 4 — Базы данных

Цель: ORM-слой на Python (мост от EF Core)

Темы

  • [ ] 4.1 SQLAlchemy — Core vs ORM, модели, сессии (мост от EF Core DbContext)
  • [ ] 4.2 Alembic — миграции (уже реально знаком — резюме упоминает Alembic и Django ORM migrations)
  • [ ] 4.3 Async SQLAlchemy — asyncpg драйвер, async-сессии
  • [ ] 4.4 Repository pattern на Python — тот же принцип, что в C#-роадмапе Фазе 6.5

🎯 Итоговое задание

Подключить SQLAlchemy + PostgreSQL к FastAPI-приложению из Фазы 3, с Alembic-миграцией и repository-слоем.

🧪 Фаза 5 — Тестирование — 🔗 частично готово

Цель: pytest-экосистема (мост от xUnit/Moq)

Темы

  • [x] 5.1 pytest основы, fixtures (есть в крэш-курсе, День 3)
  • [x] 5.2 Mocking — pytest-mock, unittest.mock (мост от Moq) (есть в крэш-курсе)
  • [x] 5.3 Coverage (есть в крэш-курсе)
  • [ ] 5.4 Integration-тесты FastAPI — TestClient/httpx.AsyncClient (мост от WebApplicationFactory)
  • [ ] 5.5 Параметризованные тесты — @pytest.mark.parametrize

🎯 Итоговое задание

Покрыть FastAPI-приложение из Фазы 3-4 unit- и integration-тестами (тот же принцип "80%+ на сервисном слое", что в C#-роадмапе Фазе 7).

🚀 Фаза 6 — DevOps

Большая часть уже знакома по C#-треку — концепции переносятся 1:1, меняется только конкретный синтаксис

Темы

  • [ ] 6.1 Docker для Python-приложений — отличия от .NET-контейнеров (нет отдельного шага компиляции)
  • [ ] 6.2 uvicorn/gunicorn — как реально запускают FastAPI в проде
  • [ ] 6.3 pydantic-settings — конфигурация через env vars (мост от C# IOptions)
  • [ ] 6.4 CI/CD — тот же GitLab CI, что и в C#-треке, просто другой build-шаг

🎯 Итоговое задание

Docker-контейнер для FastAPI-приложения + docker-compose с PostgreSQL, аналогично тому, что предполагается для Life Notes.
