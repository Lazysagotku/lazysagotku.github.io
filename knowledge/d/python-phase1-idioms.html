🎭 Аналогия

Человек, выучивший язык по словарю, говорит грамматически верно и звучит чужим. Не потому что ошибается, а потому что строит фразы по правилам родного языка. С кодом так же: цикл с индексом вместо comprehension понятен, но выдаёт человека из другой экосистемы.

📖 Теория

Изменяемое и неизменяемое

Неизменяемые Изменяемые
int, float, str, tuple, frozenset, bytes list, dict, set, объекты классов

Присвоение в Python копирует ссылку, а не значение. Это источник самой известной ловушки языка:

def add(item, target=[]):     # ЛОВУШКА: список создаётся один раз при определении
    target.append(item)
    return target

add(1)   # [1]
add(2)   # [1, 2] - тот же список

Правильно:

def add(item, target=None):
    if target is None:
        target = []
    target.append(item)
    return target

⚠️ Значения по умолчанию вычисляются один раз при определении функции. Это спрашивают почти на каждом собеседовании по Python.

Мелкая и глубокая копия:

import copy
shallow = copy.copy(data)       # вложенные объекты общие
deep    = copy.deepcopy(data)   # всё скопировано

Comprehensions

names = [v.name for v in finds if v.score > 60]
by_id = {v.id: v for v in finds}
tracks = {v.track for v in finds if v.track}

Когда идиоматично: одно преобразование плюс фильтр. Когда усложняет: два вложенных for с условиями - там обычный цикл читается лучше.

Генераторное выражение вместо списка там, где список не нужен целиком:

total = sum(v.score for v in finds)          # не строит промежуточный список
first = next((v for v in finds if v.remote), None)

*args и **kwargs

def score(*parts, **weights):
    """parts - позиционные, weights - именованные."""
    return sum(p * weights.get("k", 1) for p in parts)

score(10, 20, k=2)

Развёртывание при вызове:

args = (10, 20)
opts = {"k": 2}
score(*args, **opts)

Только именованные параметры - через *:

def publish(text, *, dry_run=False):   # dry_run нельзя передать позиционно
    ...

Это защищает от publish("текст", True), где непонятно, что означает True.

Итераторы и генераторы

Мост от C#: yield здесь работает как yield return в IEnumerable.

def read_lines(path):
    """Читает лог построчно. Файл в гигабайты не влезет в память целиком."""
    with open(path, encoding="utf-8", errors="replace") as f:
        for line in f:
            yield line.rstrip("\n")

Генератор считает по одному элементу за раз и не держит всё в памяти. Разница на большом файле - между работой и MemoryError.

itertools - то, что стоит знать:

from itertools import islice, groupby, chain, batched
islice(gen, 100)                    # первые 100 без материализации
batched(items, 1000)                # пачками, Python 3.12+
chain(list_a, list_b)               # склеить итерируемые

Декораторы

Мост от C#: атрибуты плюс обёртки, только выполняются во время исполнения.

import functools, time, logging

def timed(fn):
    @functools.wraps(fn)              # сохраняет имя и docstring
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        try:
            return fn(*args, **kwargs)
        finally:
            logging.info("%s заняло %.2f с", fn.__name__, time.perf_counter() - start)
    return wrapper

@timed
def collect(query): ...

⚠️ Без functools.wraps у обёрнутой функции пропадают __name__ и __doc__. Отладка превращается в набор функций с именем wrapper.

Параметризованный декоратор - три уровня вложенности:

def retry(times=3, delay=1.0):
    def decorator(fn):
        @functools.wraps(fn)
        def wrapper(*args, **kwargs):
            for attempt in range(times):
                try:
                    return fn(*args, **kwargs)
                except OSError:
                    if attempt == times - 1:
                        raise
                    time.sleep(delay * (2 ** attempt))   # экспоненциальная пауза
        return wrapper
    return decorator

@retry(times=5, delay=0.5)
def fetch(url): ...

Контекстные менеджеры

Мост от C#: using и IDisposable.

from contextlib import contextmanager

@contextmanager
def timing(label):
    start = time.perf_counter()
    try:
        yield
    finally:
        print(f"{label}: {time.perf_counter() - start:.2f} с")

with timing("сбор вакансий"):
    collect()

Гарантия в finally: ресурс освободится даже при исключении. Именно поэтому файлы и соединения открывают через with, а не вручную.

Несколько сразу:

with open(src) as fin, open(dst, "w") as fout:
    ...

ООП и dunder-методы

from dataclasses import dataclass, field

@dataclass(frozen=True, slots=True)
class Find:
    id: str
    name: str
    score: int = 0
    tags: tuple[str, ...] = ()

    def __str__(self) -> str:
        return f"{self.name} ({self.score})"
Что даёт Как
__eq__ и __hash__ @dataclass пишет сам, frozen=True делает объект хешируемым
__repr__ тоже пишет сам, видно в отладчике
экономия памяти slots=True убирает __dict__ у экземпляра
вычисляемое поле @property
изменяемое значение по умолчанию field(default_factory=list), никогда = []

__repr__ против __str__: первый для разработчика и отладки, второй для пользователя. Если написан только __repr__, str() возьмёт его.

Типизация

from typing import Iterable, Protocol

def top(finds: Iterable[Find], limit: int = 10) -> list[Find]:
    return sorted(finds, key=lambda f: -f.score)[:limit]

class Storage(Protocol):
    """Структурная типизация: подходит любой объект с такими методами."""
    def save(self, item: Find) -> None: ...

С 3.10: int | None вместо Optional[int], list[str] вместо List[str].

⚠️ Аннотации не проверяются во время выполнения. Проверку даёт mypy:

mypy scout/ --strict

💥 Сломай намеренно

  1. Изменяемое значение по умолчанию. Написать функцию с def add(x, target=[]), вызвать трижды, посмотреть на накопление.
  2. Убрать functools.wraps из декоратора, посмотреть fn.__name__ и на трассировку исключения.
  3. Изменить frozen=True датакласс - получить FrozenInstanceError.
  4. Положить field(default=[]) в датакласс - получить ValueError прямо при определении класса. Python здесь защищает, в обычных функциях не защищает.
  5. Прочитать большой файл через f.read() вместо построчного цикла, посмотреть на память в top.
  6. Соврать в аннотации - написать -> int, вернуть строку. Убедиться, что во время выполнения ничего не произошло, а mypy поймал.

🌍 Из жизни

Про изменяемые значения по умолчанию. Это баг, который живёт годами: функция работает правильно при каждом отдельном вызове и накапливает мусор при повторных. Ловится обычно тогда, когда кто-то замечает, что список растёт между запросами.

Про генераторы и память. Разбор лога на десять гигабайт через read() съедает десять гигабайт оперативной. На сервере с четырьмя это MemoryError или OOM killer. Построчный цикл занимает килобайты.

Про mypy на живом коде. Первый запуск --strict на существующем проекте даёт сотни ошибок и желание всё выключить. Рабочий путь: включить без --strict, починить, потом добавлять строгость по одному флагу.

❓ Вопросы с ответами

Чем изменяемые типы отличаются от неизменяемых и почему это важно?

Присвоение копирует ссылку. Изменяемый объект, переданный в функцию, меняется у всех, кто на него ссылается. Самая известная ловушка - изменяемое значение по умолчанию: оно вычисляется один раз при определении функции и живёт между вызовами. Пишу None и создаю внутри.

Что такое генератор и когда он нужен?

Функция с yield, отдающая элементы по одному без материализации. Нужен, когда данных больше, чем памяти, или когда достаточно первых нескольких элементов. В C# это тот же yield return у IEnumerable.

Зачем functools.wraps?

Переносит имя, docstring и аннотации с исходной функции на обёртку. Без него все декорированные функции превращаются в wrapper, и отладка становится мучением.

Что такое контекстный менеджер?

Объект с __enter__ и __exit__, гарантирующий освобождение ресурса даже при исключении. Аналог using с IDisposable в C#. Свой пишу через @contextmanager и try/finally вокруг yield.

Чем dataclass лучше словаря?

Явная структура, автоматические __eq__ и __repr__, проверка типов через mypy, автодополнение в редакторе. frozen=True делает объект неизменяемым и хешируемым, slots=True экономит память.

Аннотации типов что-то проверяют во время выполнения?

Нет, интерпретатор их игнорирует. Проверку даёт mypy на этапе разработки или в CI. Плюс аннотации читает FastAPI и Pydantic - там они превращаются в реальную валидацию.
