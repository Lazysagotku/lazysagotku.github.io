OSI-модель - 7 уровней

Аналогия из жизни: отправка посылки через логистическую компанию. - Физический - сам грузовик, который везёт коробку (биты по проводу/оптике). - Канальный - ярлык с адресом склада для конкретного участка пути (MAC-адрес - кому передать в пределах одного сегмента). - Сетевой - выбор маршрута между городами (IP-адрес - в какую сеть отправить). - Транспортный - гарантия, что все части посылки доехали целиком и в правильном порядке (TCP пересобирает данные). - Сеансовый - единый номер заказа, который держит диалог между отправителем и получателем, пока идёт вся посылка целиком. - Уровень представления - перевод формата/кодировки (как конвертация валюты или единиц измерения). - Прикладной - само письмо, которое видит получатель (то, с чем работает пользователь - браузер, почтовый клиент).

Порядок (снизу вверх): Физический → Канальный → Сетевой → Транспортный → Сеансовый → Представления → Прикладной.

IP-адрес и MAC-адрес

Аналогия из жизни: IP-адрес - почтовый адрес квартиры (меняется при переезде в другую подсеть/сеть). MAC-адрес - серийный номер, зашитый в паспорт устройства на заводе (не меняется, уникален для конкретного "железа").

  • IP-адрес - уникальный внутри подсети идентификатор устройства 3-го уровня OSI. IPv4 пока доминирует, IPv6 - будущее (адресов IPv4 физически не хватает на все устройства мира).
  • MAC-адрес - уникальный идентификатор устройства 2-го уровня OSI, с ним работают коммутаторы. Записывается как 12-значное шестнадцатеричное число (48 бит = 6 байт).

LAN vs WAN

  • LAN (Local Area Network) - локальная сеть в пределах одного сегмента/здания.
  • WAN (Wide Area Network) - сеть, не ограниченная географией. Интернет - классический пример WAN.

[!info]+ Уточнение В источнике LAN описан как "один широковещательный домен" - верно для простой сети БЕЗ VLAN. В реальных корпоративных сетях с VLAN один физический LAN может содержать несколько отдельных широковещательных доменов (каждый VLAN - свой домен).

DHCP и DNS

  • DHCP (Dynamic Host Configuration Protocol) - автоматически раздаёт IP-адреса устройствам в подсети (клиент запрашивает, сервер выдаёт).
  • DNS (Domain Name System) - превращает доменное имя (hh.ru) в IP-адрес, по которому реально идёт запрос.

UTP-кабель, свитч, роутер, хаб

Максимальная длина UTP-кабеля - до 100 метров на один сегмент, дальше нужен репитер или коммутатор для восстановления сигнала.

[!info]+ Не факт, а шутка "Если погода холодная, то это не точно" - юмор, не реальный инженерный фактор. Температура в разумных пределах не меняет предел в 100 метров.

Аналогия из жизни: свитч - внутренний офисный сортировщик почты, разносит письма по номерам кабинетов в пределах ОДНОГО здания (MAC-адреса). Роутер - служба доставки между городами, работает по адресам городов/улиц (IP), сам выбирает маршрут.

  • Свитч (коммутатор) - 2-й уровень OSI, работает по MAC-адресам, к нему подключают конечные устройства (компьютеры, МФУ).
  • Роутер (маршрутизатор) - 3-й уровень OSI, маршрутизирует IP-пакеты между подсетями, хранит таблицы маршрутизации.
  • Хаб - 1-й уровень OSI, просто повторяет сигнал на все порты без разбора адресов - устарел, почти не используется (каждый лишний хаб - общий домен коллизий на всех подключённых).

VLAN

Аналогия из жизни: перегородки в одном офисном опен-спейсе. Стены и провода физически общие (один физический LAN), но разные "отделы" (VLAN) логически изолированы и не слышат широковещательный трафик друг друга.

Суть: позволяет на одной физической инфраструктуре создать несколько логически изолированных сетей - экономия портов/кабелей, более чистая сегментация трафика.

[!info]+ Уточнение В источнике VLAN описан как "несколько сетей на одном порту роутера" - это частный случай (router-on-a-stick: один интерфейс роутера с несколькими подинтерфейсами через 802.1Q-транкинг). В общем случае VLAN - это прежде всего концепция КОММУТАТОРА (транковые порты свитчей), а не роутера.

Ethernet

Стандарт (точнее, семейство стандартов) для подключения устройств к проводной локальной сети - варианты отличаются в первую очередь скоростью (10BASE-T, 100BASE-TX/Fast Ethernet, 1000BASE-T/Gigabit и так далее).

TCP vs UDP

Оба - протоколы транспортного уровня (4-й уровень OSI).

  • TCP - надёжный, подтверждает доставку каждого пакета, пересобирает и упорядочивает данные. Используется там, где потеря данных недопустима (файлы, веб-страницы, почта).
  • UDP - без подтверждения доставки, допускает потерю пакетов ради скорости и низкой задержки. Используется для видео/голоса/игр, где повторная отправка потерянного пакета опоздает сильнее, чем сама потеря.

NAT

Аналогия из жизни: офисная ресепшн с одним общим номером телефона. Много сотрудников (внутренние IP) звонят наружу через один и тот же общий внешний номер (публичный IP); ресепшн (NAT) запоминает, кто именно звонил, и корректно переключает входящий ответный звонок на нужный внутренний добавочный.

Суть: позволяет множеству устройств с приватными IP выходить в интернет под одним (или несколькими) публичными IP и получать ответные пакеты обратно на правильное внутреннее устройство.

Информационная безопасность

Типы атак: DoS, DDoS, фишинг, spoofing (подмена адреса/личности), bruteforce (перебор паролей), переполнение буфера, SQL-инъекции, MITM (Man In The Middle - перехват трафика между двумя сторонами).

Вредоносное ПО: бэкдоры (скрытый доступ), майнеры (незаконный майнинг на чужих ресурсах), банкеры (кража банковских данных), шпионское ПО (Spyware), рекламное ПО (Adware), руткиты (маскировка присутствия в системе).

Прокси-сервер

Аналогия из жизни: личный секретарь, который звонит по внешним номерам ВМЕСТО тебя и передаёт тебе ответ - собеседник на другом конце общается с секретарём, а не напрямую с тобой.

Суть: посредник между клиентом во внутренней сети и сервером во внешней сети (или наоборот - обратный прокси).

Протоколы маршрутизации

  • RIP (Routing Information Protocol) - старый протокол маршрутизации, хранит информацию о сетевых путях (какая сеть подключена к какому интерфейсу роутера). Постепенно выходит из употребления из-за ограничений масштабируемости.
  • EIGRP (Enhanced Interior Gateway Routing Protocol) - проприетарный протокол Cisco, высокая масштабируемость и быстрая сходимость сети.
  • OSPF (Open Shortest Path First) - протокол внутренней маршрутизации с учётом состояния каналов (link-state IGP), используется когда RIP уже не справляется со сложностью сети.
  • BGP (Border Gateway Protocol) - соединяет автономные системы (совокупности маршрутизаторов с общей политикой) по всему интернету - протокол, на котором держится маршрутизация всего интернета.
  • MPLS (Multiprotocol Label Switching) - ускоряет пересылку трафика через метки вместо разбора IP-адреса на каждом узле, используется и для приоритизации трафика по классам обслуживания (голос/видео/транзакции).

[!info]+ Опечатка в источнике В видео сказано "да здравствует RIPv2 (рип версии один)" - это ошибка/опечатка: RIPv2 - вторая версия протокола, не первая.

QoS, SIP, RTP

  • QoS (Quality of Service) - расстановка приоритетов между классами трафика (например, голос/видео получают приоритет над обычной загрузкой файлов, так как чувствительны к задержке).
  • SIP (Session Initiation Protocol) - устанавливает и завершает сеанс связи (сигнализация для VoIP-звонков). Более гибкий и современный вариант по сравнению с ISDN PRI, но PRI дольше проверен на надёжность.
  • RTP (Real-time Transport Protocol) - передаёт сам голос/медиапоток в VoIP, обычно напрямую между конечными устройствами, пока SIP только устанавливает и завершает сессию.

DevOps и CI/CD

Аналогия из жизни: раньше разработка и эксплуатация были как два отдела, которые перебрасывают работу через стену, не разговаривая друг с другом - разработчик написал код и "перекинул" его через стену, а дальше это уже не его забота. DevOps строит мост через эту стену, чтобы обе стороны шли вместе от кода до продакшна.

Суть DevOps: модель взаимодействия тех, кто пишет код, с теми, кто его разворачивает/поддерживает в проде (серверы, сеть, инфраструктура).

Инструменты DevOps: - Сборка/тестирование - Jenkins, TeamCity, Bamboo. - Контроль версий - Git, Mercurial, Subversion, CVS. - Контейнеризация/оркестрация - Docker, Kubernetes. - Инфраструктура как код - Puppet, Chef, Ansible, Salt. - Виртуализация - Vagrant, VMware, Hyper-V. - Мониторинг - ELK-стек, Nagios, Grafana.

CI/CD: - Continuous Integration - частые небольшие коммиты в общий код, которые сразу проверяются, а не одно большое слияние раз в месяц. - Continuous Delivery - автоматическая доставка проверенных изменений в тестовые окружения (или прод) без ручной остановки всего процесса на каждое изменение.

Серверные операционные системы

Windows Server, Linux-дистрибутивы (Ubuntu, CentOS, Red Hat, Debian), FreeBSD, Solaris.

[!info]+ Шутка, не реальная ОС "BolgenOS" в видео - известный рунет-мем (пародийная "ОС" на базе взломанной Windows XP), не настоящий серверный продукт. Не стоит упоминать всерьёз на собеседовании.

LDAP и Active Directory

  • Active Directory (AD) - иерархическое хранилище данных об объектах сети (пользователи, компьютеры, группы) - сама служба каталогов (работает как серверная роль).
  • LDAP - протокол, по которому обращаются к такому каталогу (запрос/изменение данных). AD использует LDAP как один из протоколов доступа (наряду, например, с Kerberos для аутентификации).

SSH и Telnet

  • Telnet - протокол удалённого подключения к сетевому устройству для администрирования, трафик НЕ шифруется.
  • SSH (Secure Shell) - тот же смысл, но весь трафик шифруется - современный стандарт, Telnet считается небезопасным.

Виртуализация

Аналогия из жизни: одно здание, разделённое на несколько полностью независимых квартир - у каждой свой вход и коммуникации, хотя фундамент и стены общие.

Суть: на одном физическом сервере создаётся несколько изолированных виртуальных машин - лучше утилизация железа, экономия на количестве физических серверов.

RAID

Аналогия из жизни: хранить важные документы сразу в двух разных ящиках стола - если один ящик сгорит, копия во втором уцелеет.

Суть: объединение нескольких физических дисков в один логический том для отказоустойчивости и/или производительности (разные уровни RAID по-разному балансируют между "дублировать данные" и "ускорить чтение/запись, разложив данные по нескольким дискам").

Хэш-функция

Аналогия из жизни: мясорубка - один и тот же кусок мяса на входе всегда даёт одинаковый фарш на выходе, но по фаршу нельзя восстановить исходную форму куска.

Суть: преобразует входные данные произвольной длины в выходную строку фиксированной длины; по результату нельзя восстановить исходные данные (для криптографических хэш-функций - специально спроектированное свойство).

WebSocket

Протокол поверх TCP-соединения для постоянного двустороннего обмена сообщениями между браузером и сервером - без необходимости заново выполнять HTTP-запрос на каждое сообщение (в отличие от обычного REST API, где каждый вызов - отдельный HTTP-запрос).

Типы тестирования

  • Модульное (unit) - отдельные компоненты кода в изоляции.
  • Интеграционное - несколько модулей/сервисов вместе.
  • Функциональное - соответствие бизнес-требованиям.
  • Сквозное (E2E) - полный пользовательский сценарий целиком.
  • Нагрузочное (performance) - поведение системы под нагрузкой.
  • Smoke-тесты - быстрая проверка, что основные функции вообще работают, прежде чем гонять полный набор тестов.

Q&A - быстрый повтор

  • В чём разница свитча и роутера? → свитч работает по MAC (2-й уровень, внутри сети), роутер - по IP (3-й уровень, между сетями).
  • Зачем нужен NAT? → чтобы много устройств с приватными IP делили один публичный IP для выхода в интернет.
  • TCP или UDP для видеозвонка? → UDP - потеря отдельного кадра менее заметна, чем задержка от повторной отправки через TCP.
  • Чем LDAP отличается от Active Directory? → LDAP - протокол доступа, AD - сама служба каталогов (сервер), которая этот протокол среди прочих поддерживает.
  • Зачем нужен hash, если из него нельзя восстановить исходные данные? → как раз поэтому и нужен - для проверки целостности/паролей: сравнивают хэши, не сами данные.
