React — недельный крэш-курс (Мосбиржа, дедлайн ~неделя)

114 строк · источник l2code/React_Crash_Companion.md

Не полноценный курс — фокусированный план под конкретную честную договорённость с рекрутером ("могу подтянуть за неделю"). Реалистичная цель: понимать основы, объяснять их своими словами, показать один небольшой рабочий пример — не "прикинуться" опытным React-разработчиком.

Мостики от того, что ты уже знаешь

React Твой аналог из C#
Component (функция) Метод, возвращающий "модель того, что показать"
Props Параметры конструктора / init-only свойства (только читаешь, не меняешь у себя)
State (useState) Приватное mutable поле — но "запись" сама вызывает перерисовку, без ручного Refresh()
useEffect Что-то среднее между конструктором (пустой массив зависимостей = один раз) и реакцией на изменение свойства
.map() для списков LINQ .Select() — та же идея, трансформация коллекции в другую коллекцию (только тут — в UI-элементы)
JSX Синтаксический сахар — как record, просто под капотом вызовы функций, строящих дерево UI

День 1-2 — JSX, компоненты, props

Суть: компонент — функция, возвращающая JSX (HTML-подобный синтаксис внутри JS). Props — то, что передаёт РОДИТЕЛЬ, компонент их только читает.

function Greeting({ name, age }) {  // props передаются как объект
  return <h1>Привет, {name}! Тебе {age} лет.</h1>;
}

function App() {
  return <Greeting name="Иван" age={28} />; // как вызов метода с параметрами
}

Задание: сделать компонент UserCard({ name, role }), вывести карточку с именем и ролью. Отрендерить 3 разных карточки в App.

День 3-4 — State и useEffect (ядро React)

Суть: useState возвращает пару [значение, функция-сеттер]. Вызов сеттера меняет значение И запускает перерисовку компонента.

function Counter() {
  const [count, setCount] = useState(0); // как приватное поле + автоматический Refresh()
  return (
    <div>
      <p>Счётчик: {count}</p>
      <button onClick={() => setCount(count + 1)}>+1</button>
    </div>
  );
}

useEffect — сайд-эффекты (запросы, подписки, таймеры):

useEffect(() => {
  console.log("Выполнится один раз, при первом рендере");
}, []); // пустой массив зависимостей = как конструктор

useEffect(() => {
  console.log("Выполнится при КАЖДОМ изменении count");
}, [count]); // реагирует на изменение — похоже на property-changed

Задание: переделать Counter, добавить useEffect, который логирует в консоль каждое изменение счётчика.

День 5 — Запрос к API (твоя реальная сильная сторона)

Суть: сама идея запроса к REST API тебе знакома — здесь просто новая обвязка вокруг того же самого.

function UserList() {
  const [users, setUsers] = useState([]);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    fetch("https://jsonplaceholder.typicode.com/users")
      .then(res => res.json())
      .then(data => { setUsers(data); setLoading(false); });
  }, []); // один раз при загрузке компонента

  if (loading) return <p>Загрузка...</p>;

  return (
    <ul>
      {users.map(u => <li key={u.id}>{u.name}</li>)} {/* .map = твой .Select() */}
    </ul>
  );
}

Задание: вывести список пользователей с публичного тестового API (как выше), добавить обработку состояния загрузки и ошибки.

День 6-7 — Собрать маленький, но целый пример

Задание: мини-приложение "список заметок" (перекликается с Life Notes): - Форма добавления заметки (текстовое поле + кнопка) — управляемый input (value + onChange, снова useState) - Список уже добавленных заметок (.map()) - Кнопка удаления у каждой заметки

Это даёт тебе конкретный, реальный (пусть маленький) артефакт, который можно показать и объяснить на созвоне — не абстрактные "прочитал доки", а работающий код.

Что честно сказать на собесе

  • "Активно погружаюсь последнюю неделю, понимаю компоненты/props/state/hooks, собрал рабочий пример" — правда, не натяжка.
  • НЕ утверждать глубокое знание экосистемы (Redux/Router/тестирование компонентов, TypeScript+React) — этого за неделю физически не будет, и это нормально не иметь.
  • Сильная сторона — тебе не нужно объяснять, ЗАЧЕМ фронтенду дёргать API, ты это уже знаешь с бэкенд-стороны — упор туда.
