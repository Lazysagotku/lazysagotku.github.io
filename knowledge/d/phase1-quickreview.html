1.1 Value types vs Reference types

Аналогия: value type — переписал рецепт на новый листок, у каждого свой; reference type — дал ссылку на Google Docs, оба смотрят на один документ.

Суть: Value types (int, struct, enum) хранят данные напрямую, копируются целиком при присвоении. Reference types (class, array, interface) хранят адрес — копируется ссылка, оба указывают на один объект. Struct — для маленьких неизменяемых данных (~≤16 байт), иначе class.

int a = 10; int b = a; b = 20;
Console.WriteLine(a); // 10 — независимая копия

var list1 = new List<int> { 1 };
var list2 = list1; list2.Add(2);
Console.WriteLine(list1.Count); // 2 — та же ссылка

Q&A: - Что копируется при b = a для int? → значение, независимая копия. - Что копируется для List/class? → ссылка, оба указывают на один объект. - Когда выбрать struct, а когда class? → struct: маленький, неизменяемый, ~≤16 байт; иначе class.

1.2 Stack и Heap

Аналогия: стек — стопка подносов в столовой, берёшь и кладёшь только сверху; куча — большой склад с каталогом, места много, но нужен работник (GC), чтобы убирать лишнее.

Суть: Stack — быстрый, LIFO, очищается автоматически, хранит локальные переменные/ссылки/value types. Heap — управляется GC, хранит все объекты (reference types). Boxing — упаковка value type в object (аллокация в куче), unboxing — обратно; в цикле это катастрофа по производительности.

var list = new ArrayList();
for (int i = 0; i < 1_000_000; i++)
    list.Add(i); // boxing на КАЖДОЙ итерации — int упаковывается в object

var list2 = new List<int>(); // generic — без boxing вообще

Q&A: - Почему ArrayList медленнее List<int> для чисел? → boxing каждого int при добавлении в object-based коллекцию. - Что происходит со стеком после выхода из метода? → очищается автоматически; объекты на куче остаются до сборки GC.

1.3 Строки — иммутабельность

Аналогия: напечатанная книга — нельзя стереть слово в тираже, можно только напечатать новую книгу с изменением.

Суть: string — reference type, но иммутабелен: любая "модификация" создаёт НОВЫЙ объект, старый — мусор для GC. == для строк сравнивает содержимое (перегружен), ReferenceEquals — адрес. += в цикле — O(n²), решение — StringBuilder.

string result = "";
for (int i = 0; i < 10_000; i++)
    result += i; // 10 000 новых объектов в куче — O(n²)

var sb = new StringBuilder();
for (int i = 0; i < 10_000; i++)
    sb.Append(i); // один изменяемый буфер

Q&A: - string y = x; x = "changed"; — что в y? → старое значение, строки иммутабельны, x просто указывает на новый объект. - Зачем нужна иммутабельность? → безопасность ключей в Dictionary, thread-safety без блокировок, string interning.

1.4 Приведение типов

Аналогия: implicit — переливаешь из маленького стакана в большое ведро, ничего не проливается; explicit — обратно в стакан, часть может выплеснуться.

Суть: implicit — компилятор сам, без потери данных (int→long). explicit — принудительное, может терять данные ((int)3.14). as — безопасное приведение (только reference types/Nullable<T>), null при неудаче вместо исключения. is — проверка типа, с C# 7+ сразу присваивает переменную (pattern matching).

object obj = 42;
string s = obj as string;      // null — не строка, БЕЗ исключения

if (obj is int i)               // проверяет И присваивает
    Console.WriteLine(i * i);

Q&A: - Чем as отличается от явного (Type)obj? → as возвращает null при неудаче; explicit cast бросает InvalidCastException. - Работает ли as с value types напрямую? → нет, только с reference types и Nullable<T> (obj as int?).

1.5 Nullable и null-операторы

Аналогия: анкета с необязательным полем "отчество" — ?. читает, только если поле заполнено; ?? подставляет значение по умолчанию, если пусто.

Суть: value types по умолчанию не бывают null — int?/Nullable<T> оборачивает. ?. — безопасный доступ (не бросает NullReferenceException). ?? — значение по умолчанию. ??= — присвоить, только если сейчас null.

string city = user?.Address?.City ?? "Москва"; // null на любом шаге → "Москва"

List<string> items = null;
items ??= new List<string>(); // создаётся, только если был null

Q&A: - Что вернёт user?.Name?.ToUpper(), если user == null? → null, без исключения. - Чем ??= отличается от ??? → ??= присваивает переменной; ?? просто подставляет значение в выражении, ничего не меняя.

1.6 Switch expression и Pattern Matching

Аналогия: сортировочная машина на почте — посылка сама попадает в нужный лоток по категории, а не сотрудник вручную проверяет каждую цепочкой "если это, то...".

Суть: switch как ВЫРАЖЕНИЕ (не оператор) — возвращает значение через =>, компилятор проверяет полноту вариантов. Есть type patterns, property patterns, when-условия (диапазоны), tuple patterns.

string quadrant = point switch
{
    { X: > 0, Y: > 0 } => "I квадрант",
    { X: < 0, Y: > 0 } => "II квадрант",
    _ => "На оси или начало координат"
};

Q&A: - Чем switch expression отличается от классического switch? → возвращает значение напрямую, компактнее, компилятор следит за полнотой вариантов. - Что делает _ в switch expression? → catch-all/default, ловит всё, что не совпало выше.

1.7 Массивы и коллекции

Аналогия: Array — полка фиксированного размера; List — расширяемый шкаф; Dictionary — картотека с именными ярлычками, находишь папку мгновенно по имени.

Суть: Array — фиксированный размер. List<T> — динамический (внутри массив, удваивается при переполнении). Dictionary — хэш-таблица O(1) (внутри buckets+entries, resize — самая дорогая операция, задавай capacity заранее, если знаешь объём). HashSet — уникальные значения, O(1) Contains. Queue — FIFO, Stack — LIFO.

var dict = new Dictionary<string, int>(capacity: 10_000); // избегаем повторных resize
dict["Ivan"] = 28;
if (dict.TryGetValue("Ivan", out int age)) Console.WriteLine(age);

Q&A: - Почему Dictionary даёт O(1) для поиска? → хэш ключа сразу указывает нужный bucket, не перебор всех элементов. - Самая дорогая операция Dictionary? → resize — пересоздание buckets/entries и пересчёт хэшей ВСЕХ элементов. - FIFO vs LIFO — где используется? → FIFO (Queue): очередь задач, RabbitMQ. LIFO (Stack): Ctrl+Z, call stack в отладчике.

1.8 IEnumerable и foreach под капотом

Аналогия: экскурсовод ведёт группу по залам музея один за другим, не имея заранее всего плана — на каждом шаге знает, куда идти дальше (MoveNext) и что показать сейчас (Current).

Суть: foreach разворачивается в GetEnumerator() → while(MoveNext()) → Dispose() в finally. IDisposable — для ресурсов, которые GC НЕ контролирует (файлы, сокеты, БД); using — сахар над try/finally. yield return — ленивая генерация, элемент за элементом, без создания всей коллекции сразу. LINQ работает через IEnumerable, выполнение ОТЛОЖЕННОЕ — запрос не считается, пока не начнётся перебор.

IEnumerable<int> GetEvenNumbersLazy(int max)
{
    for (int i = 0; i <= max; i++)
        if (i % 2 == 0)
            yield return i; // приостанавливается здесь, возвращает по одному
}

var query = numbers.Where(n => n > 5); // ЕЩЁ НЕ выполнилось
numbers.Add(11);
foreach (var n in query) ...             // выполнится ТУТ, 11 тоже попадёт

Q&A: - Зачем Dispose, если есть GC? → GC не знает про файлы/сокеты/соединения — их нужно освобождать вручную. - Что значит "отложенное выполнение" в LINQ? → .Where(...) не считается в момент объявления, а только когда реально начинается перебор (foreach/.ToList()). - Что делает yield return? → приостанавливает метод, возвращает один элемент, не создавая всю коллекцию в памяти сразу.
