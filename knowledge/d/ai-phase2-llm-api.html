🟢 Фаза 2. Работа с LLM API (6 часов)

184 строк · источник l2code/AI_Phase2_LLM_API.md

📖 Фаза роадмапа «AI Product Engineer». Оглавление и статус - в AIEngineer_Roadmap.md. Каждая фаза самодостаточна: 🎭 аналогия → 📖 теория → 🔧 практика → 💥 сломай намеренно → ✅ задание → 🌍 из жизни → ❓ вопросы с ответами.

Цель: встроить вызов модели в код, а не только в чат. Частично пройдено практикой на разведчике.

🎭 Аналогия

Разница между разговором с консультантом и встроенным в кассу сканером. Консультант отвечает человеку, сканер отдаёт структурированные данные программе. Второму нужны схема ответа, обработка сбоев и учёт стоимости.

📖 Теория

Базовый вызов

import anthropic

client = anthropic.Anthropic()   # ключ из ANTHROPIC_API_KEY

response = client.messages.create(
    model="claude-sonnet-5",
    max_tokens=1024,
    system="Ты разбираешь вакансии. Отвечай только по тексту вакансии.",
    messages=[{"role": "user", "content": text}],
)
print(response.content[0].text)
print(response.usage.input_tokens, response.usage.output_tokens)

⚠️ usage в ответе - это счёт. Логировать его надо с первого дня, иначе расход обнаруживается по выписке.

Потоковая выдача

with client.messages.stream(model="claude-sonnet-5", max_tokens=1024,
                            messages=[{"role": "user", "content": text}]) as stream:
    for chunk in stream.text_stream:
        print(chunk, end="", flush=True)

Стриминг не ускоряет генерацию. Он меняет восприятие: первые слова появляются через секунду вместо тридцати. Для интерфейса это разница между «работает» и «завис».

Мост от C#: IAsyncEnumerable<T> - тот же паттерн потребления по частям.

Структурированный вывод

Самая полезная часть для эксплуатации: получить от модели данные, а не текст.

from pydantic import BaseModel

class VacancyBrief(BaseModel):
    track: str
    salary_min: int | None
    blockers: list[str]
    score: int

schema = VacancyBrief.model_json_schema()

Два способа добиться схемы: 1. Tool use - описать инструмент со схемой параметров, модель «вызывает» его, и параметры приходят валидными. 2. Промпт плюс валидация - попросить JSON, распарсить, при ошибке отправить обратно с текстом ошибки.

⚠️ Первый способ надёжнее. Второй нужен, когда провайдер не поддерживает инструменты.

Всегда валидировать через Pydantic, даже при использовании инструментов. Схема на стороне модели - подсказка, а не гарантия.

Tool use

tools = [{
    "name": "save_brief",
    "description": "Сохраняет разбор вакансии в трекер",
    "input_schema": {
        "type": "object",
        "properties": {
            "track": {"type": "string", "enum": ["dev", "ai", "support"]},
            "score": {"type": "integer", "minimum": 0, "maximum": 100},
            "blockers": {"type": "array", "items": {"type": "string"}},
        },
        "required": ["track", "score"],
    },
}]

Что делает инструмент хорошим: - имя глаголом, понятное без документации; - описание объясняет когда его вызывать, а не только что он делает; - схема с ограничениями: enum, minimum, required; - мало параметров - три-четыре, дальше модель начинает путаться.

Стоимость

Приём Экономия
Кэширование префикса промпта до 90% на повторяющемся контексте
Модель поменьше на простых задачах кратно
max_tokens по факту не платить за лишнее
Пакетная обработка скидка у большинства провайдеров
Убрать лишнее из контекста прямо пропорционально

Кэширование префикса - главный приём, когда системное сообщение и справочные данные одинаковы во всех запросах. Разведчик разбирает сотни вакансий с одним и тем же системным промптом - это ровно тот случай.

Ошибки и повторы

Код Что означает Что делать
429 превышен лимит частоты повтор с растущей паузой, читать retry-after
529 перегрузка сервиса повтор с паузой
400 плохой запрос не повторять, чинить
401 ключ не повторять
500 сбой на стороне провайдера повтор ограниченное число раз 
import time, random

def call_with_retry(fn, times=5):
    for attempt in range(times):
        try:
            return fn()
        except anthropic.RateLimitError:
            if attempt == times - 1:
                raise
            pause = (2 ** attempt) + random.random()   # джиттер
            time.sleep(pause)

⚠️ Джиттер обязателен. Без него все клиенты повторяют одновременно и добивают сервис, который только начал восстанавливаться.

🔧 Практика

На разведчике: 1. Вынести разбор вакансии в вызов API со структурированным ответом через tool use. 2. Валидировать ответ через Pydantic-модель, при ошибке - повтор с текстом ошибки. 3. Логировать usage каждого вызова в таблицу: модель, токены, оценка стоимости. 4. Включить кэширование префикса на системном сообщении, замерить разницу в токенах. Записать цифры. 5. Обёртка повторов с экспоненциальной паузой и джиттером на 429 и 529. 6. Посчитать реальную стоимость разбора ста вакансий.

Отдельно: 7. Консольный инструмент, который стримит ответ и корректно отменяется по Ctrl+C.

💥 Сломай намеренно

  1. Попросить JSON промптом без валидации и подсунуть вакансию с кавычками внутри - получить сломанный разбор.
  2. Убрать max_tokens или поставить огромный - посмотреть на счёт за один длинный ответ.
  3. Сделать повторы без джиттера и запустить двадцать параллельных вызовов - получить лавину 429.
  4. Повторять при 400 - убедиться, что это бесконечный цикл на неисправимой ошибке.
  5. Описать инструмент с восемью параметрами и посмотреть, как модель начинает их путать.
  6. Выключить кэширование префикса и сравнить токены на ста однотипных запросах.

✅ Задание

Разведчик разбирает вакансии через API со структурированным выводом, валидацией, повторами и логом расхода. В README записана стоимость разбора ста вакансий и экономия от кэширования.

Критерий: называешь цифру стоимости и объясняешь, из чего она складывается.

🌍 Из жизни

Про неучтённый расход. Типичная история: прототип запустили в цикл по большому набору данных, забыли лимит, счёт обнаружили через неделю. Логирование usage с первого дня закрывает это.

Про JSON промптом. Модель почти всегда возвращает валидный JSON и иногда добавляет пояснение до или после. Парсер падает раз в сто вызовов, и это ловится в проде, а не в тестах. Tool use убирает класс проблемы целиком.

Про кэширование префикса. На однотипной обработке, где системное сообщение занимает больше входа, экономия достигает разов. Для разведчика с сотнями вакансий и одним промптом это прямая экономия.

❓ Вопросы с ответами

Как получить от модели структурированный ответ?

Через tool use: описываю инструмент со схемой параметров, модель его вызывает, параметры приходят по схеме. Дополнительно валидирую через Pydantic - схема на стороне модели это подсказка, а не гарантия. Промпт с просьбой вернуть JSON работает хуже: модель иногда добавляет пояснение вокруг.

Зачем стриминг, если он не ускоряет?

Он меняет восприятие. Первые слова появляются через секунду вместо тридцати, и интерфейс выглядит работающим, а не зависшим. На скорость генерации не влияет.

Как контролируете стоимость?

Логирую usage каждого вызова с первого дня. Кэширую префикс промпта там, где системное сообщение одинаковое - на однотипной обработке это даёт разы. Простые задачи отдаю модели поменьше, max_tokens ставлю по факту.

Как обрабатываете ошибки API?

Развожу повторяемые и неповторяемые. 429 и 529 - повтор с экспоненциальной паузой и джиттером, читаю retry-after. 400 и 401 не повторяю, там надо чинить. Джиттер обязателен: без него все клиенты повторяют синхронно и добивают сервис.

Что делает инструмент хорошим для модели?

Имя глаголом, описание отвечает на вопрос «когда его вызывать», схема с ограничениями через enum и границы, и мало параметров. С восьмью параметрами модель начинает их путать.
