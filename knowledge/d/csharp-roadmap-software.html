🌐 Фаза 5 — Backend (.NET / ASP.NET Core) — 🔄 В АКТИВНОЙ РАБОТЕ

Цель: уметь писать API и серверные приложения Строится прямо сейчас внутри Life Notes (Web API на ASP.NET Core + EF Core + PostgreSQL) — не с чистого листа, а параллельно с уже идущими откликами на собеседования.

Темы

  • [ ] 5.1 .NET платформа — CLR, JIT, сборка мусора (GC)
  • 📝 Life Notes: Life Notes — не консольный скрипт, а долгоживущий серверный процесс. Понимание GC объясняет, почему поведение памяти отличается от Phase 1 примеров.
  • [ ] 5.2 ASP.NET Core — структура проекта, middleware, DI
  • 📝 Life Notes: это буквально скелет самого приложения — конвейер, через который пройдёт каждый запрос "создать/получить/удалить заметку".
  • [ ] 5.3 Dependency Injection — IoC контейнер, жизненные циклы (Singleton, Scoped, Transient)
  • 📝 Life Notes: NoteService/UserService нужно правильно связать между собой — перепутать Scoped/Singleton для DbContext = реальный класс production-багов ("общий DbContext на все запросы").
  • [ ] 5.4 REST API — контроллеры, маршрутизация, статус коды
  • 📝 Life Notes: сам интерфейс, через который заметки создаются/читаются/обновляются/удаляются — GET /notes, POST /notes, корректные 201/404 вместо "всегда 200".
  • [ ] 5.5 Minimal API (современный подход)
  • 📝 Life Notes: можно сравнить оба подхода на одном маленьком эндпоинте (например health-check) — на собесе иногда спрашивают, чем отличаются.
  • [ ] 5.6 Конфигурация — appsettings.json, переменные окружения, IOptions
  • 📝 Life Notes: строка подключения к БД и JWT-секрет никогда не хардкодятся — учит правильному разделению dev/prod настроек с нуля.
  • [ ] 5.7 Логирование — ILogger, Serilog
  • 📝 Life Notes: когда заметка не сохранилась или поиск сломался — нужны структурированные логи, а не гадание. Раньше уже был закрыт как найденный гэп (Сачков-видео).
  • [ ] 5.8 Middleware — написание своего
  • 📝 Life Notes: свой middleware для глобальной обработки ошибок (чистый JSON вместо голого stack trace) или логирования длительности каждого запроса.
  • [ ] 5.9 Аутентификация — JWT, Cookie Auth
  • 📝 Life Notes: заметки — личные, нужно реально знать, ЧЬИ они. Здесь появляется настоящая защита эндпоинтов, не декоративная.
  • [ ] 5.10 Background Services — IHostedService, Worker Service
  • 📝 Life Notes: например фоновая переиндексация заметок для поиска или очистка старой корзины — работа, которая не должна блокировать обработку обычных запросов.

🗄️ Фаза 6 — Базы данных

Цель: уметь работать с данными профессионально

Темы

  • [ ] 6.1 ADO.NET — основы (понять что под капотом)
  • 📝 Life Notes: объясняет, что EF Core реально делает "под капотом" при обращении к Postgres — снимает ощущение магии.
  • [ ] 6.2 Entity Framework Core — Code First, миграции, DbContext
  • 📝 Life Notes: основной способ хранить заметки в Postgres — схема будет реально эволюционировать (добавятся теги/папки), миграции здесь не абстрактный пример, а рабочий процесс.
  • [ ] 6.3 LINQ to Entities — запросы через EF
  • 📝 Life Notes: поиск по тегу, фильтр по дате, сортировка по последнему изменению — всё пройдёт через это. Разница IQueryable (уходит в SQL) vs IEnumerable (в памяти) здесь не теория, а реальная ловушка производительности на растущей таблице.
  • [ ] 6.4 Dapper — легковесный ORM для сложных запросов
  • 📝 Life Notes: если EF сгенерирует неэффективный SQL для сложного поиска по заметкам — можно спуститься до Dapper за прямым контролем.
  • [ ] 6.5 Репозиторий паттерн — Repository + Unit of Work
  • 📝 Life Notes: тот же DIP-принцип из Phase 2 Contact Manager, но уже на реальном масштабе — логика хранения заметок отделена и тестируема.
  • [ ] 6.6 Транзакции и параллельный доступ
  • 📝 Life Notes: что если одну заметку редактируют с двух устройств одновременно? Настоящий вопрос конкурентного доступа, не гипотетический.
  • [ ] 6.7 Оптимизация запросов — индексы, N+1 проблема
  • 📝 Life Notes: список заметок + их теги в цикле — классическое место, где N+1 прячется. Здесь это можно реально поймать и починить, не только пересказать теорию с мок-собеса.
  • [ ] 6.8 SQLite (для desktop) / PostgreSQL (для backend)
  • 📝 Life Notes: сразу PostgreSQL, не SQLite — целевая вакансия требует именно это, учимся на проде-уровне с первого дня.

  • 📝 Life Notes: НЕ относится — Life Notes веб-API, не десктоп. Низкий приоритет, можно пропустить без потерь.
  • [ ] 8.5 NuGet — создание и публикация пакетов
  • 📝 Life Notes: актуально только если вынести переиспользуемый кусок (например DTO/валидацию) в отдельный пакет — не приоритет сейчас.
  • [ ] 8.6 Версионирование — SemVer
  • 📝 Life Notes: пригодится, если появятся версии самого API — сейчас достаточно знать теорию, без практики.

🏛️ Фаза 9 — Архитектурные паттерны

Цель: мыслить системно

Темы

  • [ ] 9.1 Паттерны проектирования — Creational, Structural, Behavioral (GoF)
  • 📝 Life Notes: учит НАЗЫВАТЬ паттерны, которые уже наверняка появятся сами по себе (Repository, Strategy для форматирования заметок) — легче обсуждать свой же код на собесе.
  • [ ] 9.2 Clean Architecture — слои, зависимости
  • 📝 Life Notes: по мере роста держит доменную логику независимой от EF Core/ASP.NET деталей — тестируемо и заменяемо, не срослось намертво.
  • [ ] 9.3 DDD основы — Domain, Application, Infrastructure слои
  • 📝 Life Notes: реальные доменные понятия (Note, Tag, Folder, User) — мыслить в терминах домена, а не только "таблицы БД".
  • [ ] 9.4 CQRS + MediatR — 🆕 теория подтянута к Фазе 6 (собес), практика здесь как обычно
  • 📝 Life Notes: разделить "получить мои заметки" (запрос) от "создать заметку" (команда) по мере роста функциональности — паттерн, который рынок явно ценит (банк вопросов Ozon).
  • [ ] 9.5 Event-driven архитектура
  • 📝 Life Notes: например событие "заметка создана" запускает фоновую переиндексацию для поиска — асинхронная реакция вместо всего подряд внутри одного запроса.
  • [ ] 9.6 Microservices vs Monolith — когда что выбрать
  • 📝 Life Notes: остаётся монолитом (правильно для pet-проекта) — но нужно уметь ОБЪЯСНИТЬ это решение на собесе, не просто сделать по умолчанию.
  • [ ] 9.7 🆕 Kafka vs RabbitMQ
  • 📝 Life Notes: Фаза 5 плана добавляет RabbitMQ реально — например асинхронная задача "экспортировать заметку в PDF". Не только концепция, а конкретная интеграция.
  • [ ] 9.8 🆕 gRPC vs REST
  • 📝 Life Notes: скорее всего останется только теорией — REST правильный выбор для публичного API заметок. Полезно уметь объяснить, ПОЧЕМУ не gRPC — классическая ловушка "оверинжиниринга" из SystemDesign_Companion.md.
  • [ ] 9.9 🆕 Polly — retry, circuit breaker, timeout, fallback
  • 📝 Life Notes: если появится вызов внешнего сервиса (например AI-инсайты по заметке через Claude API — прямая связь с твоим AI-интересом) — нужна устойчивость к сбоям, не просто try/catch и надежда.
  • [ ] 9.10 🆕 GitLab CI/CD
  • 📝 Life Notes: сама демка скорее всего останется на GitHub Actions, но GitLab — то, что реально используют российские работодатели (по рыночному анализу) — знать по названию и структуре важно для собеса.
